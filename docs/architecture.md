# rastflow 架构

rastflow 仅面向 Windows。交付一个 `rastflow.exe`，包含普通用户桌面入口和由 SCM 启动的 `--index-service` 入口。安装与卸载入口只负责维护服务，不是常驻角色。

## 进程边界

| 桌面进程 | Windows 服务 |
| --- | --- |
| GPUI、托盘、热键、应用发现和启动 | 卷发现与身份查询 |
| 文件内存索引、查询、排序 | MFT 枚举、USN 补读和跟随 |
| SQLite、用户设置、分卷快照 | 批量返回元数据，不保存完整索引 |

桌面每个 Windows 会话保持单例。再次执行只发送激活消息。服务独立运行；桌面退出后，服务释放会话和卷任务，回到等待连接状态。不再提供一次性提权索引 helper。

## 模块

- `application`：平台回调向 GPUI 投递事件，主循环异步等待事件。
- `platform`：桌面单例及 Shell 启动；文件目标不经过 cmd。
- `app_list`：发现和合并，原生目录通知与低频校准。
- `catalog`：稳定目标身份、来源标记、SQLite 事务及迁移。
- `layout`：视图、列表代理和文件搜索集成。
- `search/index`：紧凑目录项、文件引用、路径与快照。
- `search/engine`：单写入路径、扫描代次、查询和分卷恢复。
- `search/protocol`、`model`：与 UI 和 Windows API 无关的消息模型及编解码。
- `search/helper`：服务连接及同步管道；`helper_main`：服务会话。
- `search/win`：卷、USN、SCM、管道与进程 API。
- `storage`：刷新临时文件后原子替换，保留上一代。
- `diagnostics`：滚动日志，每文件约 2 MiB，保留一代，单条消息限制 16 KiB。

库与桌面 binary 共享核心实现，不重复编译两份业务模块。平台无关单元测试可以在非 Windows 构建机运行，这不代表应用支持非 Windows。

## 线程与状态

GPUI 主线程持有窗口、托盘、热键和界面状态。托盘、热键、设置、更新结果和索引状态通过事件唤醒主线程，不使用 50 ms 主循环轮询。索引状态订阅采用容量为 1 的失效通知，接收方读取最新状态。

桌面索引协调线程负责连接、补读、扫描、变更应用和检查点保存；不会在重连时再启动第二条索引泵线程。连接失败采用 1–30 秒退避，安装服务后可唤醒重试。退出请求取消阻塞 I/O 并等待有界时间保存状态。

每个搜索引擎只有一个查询工作线程、一个待执行槽位。新查询替换排队中的旧查询；界面保留请求代次，过期结果不能覆盖当前输入。查询分块读取索引，在块之间释放锁。

SQLite 由专用线程持有连接；设置由独立串行写入线程保存。Shell 图标由单一 OS/COM 工作线程处理，队列容量 32；仅为渲染到的应用行申请图标，缓存容量 512，失败缓存 30 秒。

## 应用目录

应用来源为用户/公共开始菜单、打包应用和自定义条目。启动目标用于匹配身份，显示名称不参与可启动条目的身份；合并时沿用已保存 ID 和启动次数。

不同目标的同名应用保留。快捷方式保留原始启动语义，交给 Shell；打包应用保留 AppsFolder 目标。来源字段独立于显示类别，修改类别不会把自定义条目变成自动清理对象。

启动时后台加载和校准，目录通知去抖后刷新，另每五分钟校准一次。窗口激活只过滤内存目录。SQLite 采用事务 upsert，保留自定义条目，清理消失的发现条目；启动次数独立递增，旧目录快照不会降低已保存次数。

## 文件搜索

文件名和路径匹配使用内存索引；查询不遍历目录、不调用磁盘存在性检查、不删除索引。结果为有界 Top-K，名称精确匹配优先于前缀、子串，类型优先级作为辅助，名称和路径提供稳定顺序。

服务不可用时应用启动功能正常。已有索引可以搜索，但实时更新不可用。重建在暂存索引中进行，旧代次继续可查；扫描期间变更补齐后才发布。具体见 [搜索引擎](search-engine.md)。

## 权限

服务运行于 LocalSystem。命名管道拒绝远程客户端；客户端核对管道服务端 PID 与 SCM 注册服务进程一致。服务校验客户端映像来自同一安装路径，此检查不等同于代码签名验证，安装目录应使用系统保护位置。

启用全卷索引会让桌面进程得到卷内文件名，包括可能无权打开的文件名称。未实现按文件 ACL 隐藏名称；实际访问和启动由 Windows 检查当前用户权限。服务不提供任意文件内容读取或命令执行。

## 持久化与安装

用户数据位于 `%LOCALAPPDATA%\rastflow`：`applist.db`、`settings.json`、`index/volume-*.dat`、`desktop.log`。服务日志位于 `%PROGRAMDATA%\rastflow\service.log`。日志不主动记录搜索输入或环境变量。

偏好包含主题、语言、热键和格式版本；开机自启状态从 Windows 实际配置读取。设置与索引采用 `.tmp` 原子替换及 `.bak` 恢复。旧快照格式不强行解释，会重新建库。

WiX MSI 注册和启动服务；升级/卸载先停止服务再替换 exe。服务未及时停止时维护操作失败，不继续修改运行中服务配置。用户数据默认保留。

## 验证

- 纯逻辑与存储：`cargo test --lib --locked`（非 Windows 构建机只运行平台无关核心）。
- Windows：`cargo build --locked`、`cargo clippy --locked --all-targets --all-features`、`cargo test --locked`。
- 实际 Windows 验收：热键、DPI、中文输入、Explorer 重启、NTFS 扫描/增量、服务重启、卷身份变化及 MSI 升级回滚。

交叉编译成功不等于服务、桌面和安装器已在 Windows 上通过运行验证。GUI 和 SCM 仍需实际 Windows 环境。
